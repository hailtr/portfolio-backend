## The Problem

Chartmetric's data stack had grown organically across Snowflake, PostgreSQL, and ClickHouse — with no unified observability and significant waste. Snowflake queries for Spotify and YouTube tables were running full-refresh, computing for hours, failing, and burning **$4K/month** for nothing. Meanwhile, there was no systematic way to know when a data source went stale or a pipeline silently broke.

The platform needed three things at once: migrate analytics off Snowflake, eliminate waste, and build observability from scratch.

## Snowflake → ClickHouse Migration

Led the ongoing migration of 678 analytics tables from Snowflake to ClickHouse. This isn't a lift-and-shift — every table is converted to incremental processing, eliminating the full-refresh pattern that was burning Snowflake credits.

**Incremental, not full-refresh.** Each migrated table switches from full-refresh to incremental updates using ClickHouse materialized views and ReplacingMergeTree tables. This alone eliminated $4K/month in wasted Snowflake compute.

**Parallel validation.** Every table runs in parallel on both Snowflake and ClickHouse during migration. Snowflake serves as the validation oracle until the ClickHouse version proves consistent.

**288 tables migrated so far** — covering Spotify, YouTube, TikTok, Shazam, Instagram, and dozens of other sources. The remaining 390 tables are queued for migration. The full migration targets **~$12K/month** in Snowflake savings — the current cost of the Analytics_Daily workload alone.

## Watchdog — Observability From Scratch

Before Watchdog, monitoring 38 data sources meant manually inspecting pipelines daily — checking for silent failures, stale data, broken feeds. The data alert channel was noise. I spent months firefighting issues that should have been caught automatically.

Built the Watchdog observability system that monitors data freshness, SLA compliance, and pipeline health across **38 data sources**. Now the system tells me what's failing instead of me hunting for it.

**Source registry.** A centralized registry on S3 defines expected freshness windows, SLA thresholds, and alert rules for each source. Adding a new source means adding a JSON entry — no code changes.

**From chaos to stability.** Compare the data alert channel before and after — months of daily firefighting replaced with quiet, reliable monitoring. When something actually breaks, the right people know immediately.

## ViewStats — New Product From Scratch

Built the ViewStats product end-to-end — a standalone analytics product that required its own data pipeline, storage layer, and API surface. Delivered from zero to production as a solo effort.

## Infrastructure Wins

Beyond the migration, shipped several critical infrastructure fixes:

- **Shazam timestamp corruption** — Diagnosed a DateTime64(9) → Parquet mis-scaling bug that had silently garbled timestamps in Snowflake. Fixed the wire format, backfilled affected tables, and regenerated data feeds.
- **PG → SF schema drift** — Discovered that positional COPY INTO silently misaligns columns whenever PostgreSQL adds a column. Built detection tooling and documented the systemic fix.
- **TikTok bigint migration** — Migrated 3 columns from int to bigint via zero-downtime table-swap when video IDs outgrew 32-bit integers.
- **ClickHouse Cloud contract** — Leading ongoing contract negotiations, proxy vendor selection, and data share lifecycle management.
