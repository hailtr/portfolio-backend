## The Problem

Chartmetric's product depends on fresh, comprehensive data from every major music platform. These platforms don't offer APIs for the data we need — or their APIs are rate-limited to the point of uselessness. The only path is large-scale web scraping, but every platform actively fights it with increasingly sophisticated anti-bot defenses.

The company needed someone who could break through any wall, keep pipelines running at scale, and recover fast when platforms changed their defenses.

## Ticketmaster — The Impossible One

Ticketmaster is widely considered the most difficult website to scrape on the internet. Their anti-bot defenses are among the most aggressive in the industry. Before I arrived, Chartmetric had no Ticketmaster data.

I made it possible. The pipeline now reliably extracts event and ticketing data at scale. When their defenses evolve, so does the scraper. Continuous data flow since launch.

## Discogs — The 7-Month Puzzle

Another engineer had been trying to crack Discogs for 7 months without success. The core challenge is a coordination problem — you need to orchestrate 5 scrapers to consume within Discogs' rate-limiting rules simultaneously. It's essentially a mathematical optimization problem: each scraper needs to respect per-endpoint and global limits while maximizing collective throughput.

I solved the coordination problem and built the pricing data pipeline for the Discogs marketplace, unlocking a new revenue stream for the company.

## TikTok — Total Outage Recovery

TikTok's user ingestion pipeline went completely dark — zero data flowing for weeks. The platform had deployed new anti-scraping measures that broke the existing approach entirely.

TikTok scraping requires deep understanding of the platform — cookies, harvesting, endpoints, API consumption, request mapping. The challenge isn't just getting in, it's staying in at scale while managing throttling.

I restored full data flow and reduced proxy costs from **$1,500/month to $50/month** — a 97% cost reduction while achieving higher success rates than before.

## Tunefind — API + HTML at Scale

Tunefind looks simple on the surface — match API data with HTML scraping for enrichment. In practice, it requires a massive infrastructure to maintain. Two legacy pipelines (PostgreSQL and ClickHouse) needed to be consolidated, and the unified pipeline needed proper alerting and data quality checks to catch mismatches between API and HTML sources.

Consolidated both legacy pipelines into a single, reliable pipeline with full observability.

## Shazam — Millions of Requests, Done Right

Shazam is about scale. Millions of requests flowing daily — done right, it runs smoothly and cheaply. Done wrong, it costs $5,000 a day in proxies. The difference is architecture and cost discipline.

Built the pipeline feeding data into both PostgreSQL and ClickHouse. Along the way, diagnosed and fixed a timestamp corruption bug that had silently garbled data in Snowflake for months.

## Genius — Precision Throttling

Genius is brute force — but precise brute force. Push too hard and the pipeline breaks. Push too little and data arrives late. The challenge is finding and maintaining the exact throttle balance, implementing smart per-token budgeting to maximize throughput right at the edge of what the platform allows.
